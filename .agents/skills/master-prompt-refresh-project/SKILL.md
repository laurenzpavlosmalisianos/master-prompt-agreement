# Master Prompt Agreement Project Refresh

1. Read `../../../runtime/operative_charter.md` from the explicitly selected framework checkout.
2. After loading the charter and before loading generated project authority or state, resolve the target project root without opening generated authority and check for `<project-root>/.mpa-bootstrap-recovery.json`, `<project-root>/.mpa-bootstrap.lock`, and `<project-root>/.mpa-bootstrap-recovery.tmp`. If any exists, stop ordinary work and permit only bounded read-only recovery-status inspection through `../../../scripts/project_refresh.py inspect` and, only when inspection reports a permitted recovery action and exact transaction ID, recovery through `recover --action rollback|finalize --approve-transaction-id <transaction-id>`, using a runner already supplied by the runtime or operator without reading generated project authority. If no such runner is available or inspection identifies no permitted recovery action, report the blocker and await direction; do not edit or delete a transaction-control artifact manually.
3. Read `../../../UPDATING.md`.
4. Read `../../../task_orders/framework_refresh.md`.
5. Follow the refresh Task Order exactly as the workflow source of truth. This skill grants no additional authority and defines no update or recovery procedure of its own.
6. Require one verified complete current-format retained-input/root-receipt pair with an intact recorded preimage before planning refresh. Route an absent, partial, malformed, inconsistent, older, or unrecognized instance to a separately reviewed manual project update; route a clearly newer format to a framework checkout that supports it; and treat receipt mismatch or managed-file drift in a current-format instance as invalid current state requiring bounded diagnosis, recovery when the recorded transaction state permits it, or reviewed correction. Do not route any of these cases through initialization, force rendering, state reset, or a compatibility branch. Use `master-prompt-new-project` only for first-time framework setup.
7. Keep retained input unchanged for a framework-only refresh. For an authorized contract revision, use a complete temporary candidate. Preserve retained mutable state by default. Retire optional mutable state only through its path-specific action and warning plus a verified exact-preimage bundle that makes it exactly restorable. Retire optional immutable output only under the exact plan's approved basis: either a verified bundle that makes it exactly restorable, or `ACCEPT-NO-POST-APPLY-BACKOUT` binding the exact plan, path-specific action and warning, current preimage digest and mode, and verified post-apply absence; the exception has no post-success restoration. Preview the exact generated changes, obtain approval for the exact plan digest and every named action and warning, apply once transactionally, and finish with exact-current inspection.
